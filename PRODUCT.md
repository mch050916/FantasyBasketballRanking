# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Existing: a Python script (`scripts/build_draft_board.py`) generates a single self-contained HTML file (`draft_board_2026_27.html`) with all data embedded inline — no server, no network, no build step, works fully offline. Preserve this generation model in the redesign: the visual world changes, but the output stays a single static HTML file the script writes, safe to open with no internet connection during a live draft.

## Users

Just the owner (Chester) — a single personal user, not shared with league mates. Used live, solo, during his own fantasy draft.

## Product Purpose

A draft-day reference tool: surfaces DURANT-model player rankings (a variance-penalized alternative to plain z-score rankings, see README.md) for a 14-category custom head-to-head fantasy basketball league, so the user can make fast pick decisions during a live draft without leaving the page. Separate tabs cover veterans and rookies. Success is fast lookup and comparison at the table during a draft — not analysis at leisure.

## Positioning

Not a generic rankings list — the DURANT methodology penalizes week-to-week statistical volatility (a player who swings between big and small weeks scores lower than a steady producer with the same average), which matters specifically for weekly head-to-head leagues. The board also surfaces per-player category strength/weakness tags derived from that same model, tuned by hand against real players (see `TAG_EXCLUDE` in `scripts/build_draft_board.py`) rather than exposing all 12 categories naively.

## Operating Context

Opened as a local file in a browser during a live snake/auction draft, one continuous session, likely on a laptop, possibly without reliable WiFi. Needs to support: searching/filtering players by name, marking players as drafted as the draft proceeds (state lives only in that session), switching between veteran and rookie pools, and scanning per-category strengths/weaknesses at a glance. Regenerated each season by rerunning the build script after the ranking pipeline updates.

## Capabilities and Constraints

- Data is fully embedded at build time (JSON baked into the HTML) — no live data fetching, no backend.
- Must keep working with zero network access.
- Current data surface per player: rank, DURANT total value, per-category per-game stats/z-scores (12 categories: PTS, REB, AST, ST, BLK, TO, FG%, FTM, 3PM, DD, TD, TECH), derived strength/weakness tags, position, team, drafted/not-drafted state.
- Two player pools shown as tabs: veterans and rookies (rookies use draft-slot tiers rather than a 1-N rank, since rookies within a bucket share identical baseline projections).
- Redesign is visual only — this session's scope is a new look and feel, not new functionality or data.

## Evidence on Hand

Real embedded ranking data for the 2026-27 season: `durant_rankings_2026_27.csv` and `durant_rankings_rookies_2026_27.csv`, sourced from Basketball Reference season totals plus NBA API game logs. The current implementation (`draft_board_2026_27.html`, generated by `scripts/build_draft_board.py`) is the incumbent visual system — treated as anti-reference only per the redesign request, not preserved.

## Product Principles

- Speed of scanning beats depth of analysis — this is used under draft-clock pressure, not for leisurely study.
- Offline-first: no dependency on network access ever, at build or at runtime.
- Data integrity over decoration — the DURANT model's category tags and values are hand-tuned and meaningful; a redesign must not visually flatten or obscure per-category distinctions.
- Single-user tool — no multi-user, sharing, auth, or account concerns apply.

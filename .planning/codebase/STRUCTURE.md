# Codebase Structure

**Analysis Date:** 2026-04-10

## Directory Layout

```text
FantasyBasketballRanking/
├── main.py                     # Pipeline entrypoint
├── config.py                   # League settings and cache names
├── data.py                     # CSV loading, NBA API fetches, derived stats
├── model.py                    # Projection logic and DURANT scoring
├── output.py                   # Console formatting and CSV export
├── validate.py                 # Rank comparison helpers
├── requirements.txt            # Python dependencies
├── README.md                   # User-facing setup and usage guide
├── tests/                      # Unit tests for core modules
├── basketball_reference_*.csv   # Season totals inputs
├── actual_*.csv                # Validation snapshots
├── yahoo_25_26_market_export.csv # External comparison input
├── openspec/                   # OpenSpec configuration
├── .codex/                     # Agent and workflow support files
└── .planning/                  # Generated planning documents
```

## Directory Purposes

**Repository root:**
- Purpose: Keep the project intentionally flat so the ranking pipeline is easy to run and inspect.
- Contains: All executable modules, CSV inputs, validation exports, and user documentation.
- Key files: `main.py`, `config.py`, `data.py`, `model.py`, `output.py`, `validate.py`, `README.md`.
- Subdirectories: `tests/`, `openspec/`, `.codex/`, `.planning/`.

**`tests/`:**
- Purpose: Unit coverage for the public helpers in the core modules.
- Contains: `test_data.py`, `test_model.py`, `test_validate.py`.
- Key files: `tests/test_data.py`, `tests/test_model.py`, `tests/test_validate.py`.
- Subdirectories: None.

**`openspec/`:**
- Purpose: OpenSpec project metadata.
- Contains: Configuration for spec-driven workflows.
- Key files: `openspec/config.yaml`.
- Subdirectories: `changes/`, `specs/`, including archive content under `openspec/changes/archive/`.

**`.codex/`:**
- Purpose: Local Codex agent, workflow, and skill assets.
- Contains: GSD agents, skill definitions, templates, and supporting workflow material.
- Key files: `.codex/agents/gsd-codebase-mapper.md` and the various `.codex/skills/*/SKILL.md` files.
- Subdirectories: Broad support tree used by the workspace tooling.

**`.planning/`:**
- Purpose: Generated planning artifacts for the GSD workflow.
- Contains: Codebase docs and other planning outputs.
- Key files: `.planning/codebase/ARCHITECTURE.md`, `.planning/codebase/STRUCTURE.md`.
- Subdirectories: `codebase/`.

## Key File Locations

**Entry Points:**
- `main.py`: Single runnable entrypoint for the ranking pipeline.

**Configuration:**
- `config.py`: League size, category weights, season weights, qualification thresholds, and cache file names.
- `requirements.txt`: Python dependency list.
- `README.md`: Setup and season-update instructions.

**Core Logic:**
- `data.py`: BBR CSV ingestion, NBA API access, normalization, and derived stat helpers.
- `model.py`: Projection, variance, and final G-score math.
- `output.py`: Ranking display and CSV writing.
- `validate.py`: Validation metrics and rank matching.

**Testing:**
- `tests/test_data.py`: Name normalization, lookup resolution, and missing-log detection.
- `tests/test_model.py`: FG% projection and TECH variance behavior.
- `tests/test_validate.py`: Validation matching and ranking helpers.

**Documentation and Data:**
- `README.md`: User guide and season maintenance notes.
- `basketball_reference_2024_25_total_stats.csv`: Most recent committed season totals.
- `basketball_reference_2023_24_total_stats.csv`: Prior season totals.
- `actual_14cat_24_25_snapshot.csv`, `actual_14cat_23_24_snapshot.csv`, `actual_9cat_24_25.csv`: Validation sources.
- `yahoo_25_26_market_export.csv`: External market comparison source.

## Naming Conventions

**Files:**
- `*.py` at the repository root for the pipeline modules.
- `test_*.py` under `tests/` for unit tests.
- `*.csv` at the repository root for committed season data and validation inputs.
- `*_cache.pkl` for local runtime caches generated by the NBA API fetch layer.

**Directories:**
- Flat top-level module layout instead of nested source packages.
- Lowercase directory names for supporting folders such as `tests/`, `openspec/`, `.codex/`, and `.planning/`.

**Special Patterns:**
- `main.py` is the only runnable entrypoint.
- `config.py` is the season-tuning file and should be the first place to edit league settings.
- `actual_*` and `yahoo_*` CSVs are reference artifacts, not source code.

## Where to Add New Code

**New ranking logic:**
- Primary implementation: `model.py`.
- Data preparation: `data.py` if the new logic depends on new inputs or derived stats.
- Tests: `tests/test_model.py` or a new `tests/test_*.py` file.

**New data source or API integration:**
- Primary implementation: `data.py`.
- Configuration: `config.py` if the fetch needs new seasons, limits, or cache paths.
- Tests: `tests/test_data.py`.

**New output format or report:**
- Primary implementation: `output.py`.
- Orchestration: `main.py` if the new artifact should be produced during the pipeline run.
- Tests: `tests/test_validate.py` or a new output-focused test file if formatting is added.

**New validation target:**
- Primary implementation: `validate.py` or the `VALIDATION_TARGETS` list in `main.py`.
- Data file: repository root CSV alongside the existing validation snapshots.
- Tests: `tests/test_validate.py`.

**New season refresh:**
- Update `config.py` for season weights, game-log seasons, limits, and cache names.
- Update `main.py` for the BBR file list and output filename.
- Add committed CSV inputs at the repository root.

## Special Directories

**`tests/`:**
- Purpose: Fast unit checks for the name handling, projection, and validation helpers.
- Source: Maintained manually alongside the source modules.
- Committed: Yes.

**`_cache.pkl` files at the repository root:**
- Purpose: Local caches for NBA API game logs and TECH estimates.
- Source: Written by `data.fetch_game_logs()` and `data.fetch_tech_per_game()`.
- Committed: No, treated as disposable runtime artifacts.

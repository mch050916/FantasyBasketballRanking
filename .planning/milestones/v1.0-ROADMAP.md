# Milestone v1.0: Trustworthiness And Accuracy Baseline

**Status:** SHIPPED 2026-04-30  
**Phases:** 1-5  
**Total Plans:** 10

## Overview

This milestone treated the existing DURANT ranker as brownfield software and focused on making the pipeline trustworthy, benchmark-aware, and easier to improve with evidence. The work started with reliability guardrails, then strengthened cross-source identity and benchmark fidelity, then added persistent miss diagnostics, and finally upgraded the projection and milestone-stat calibration logic.

## Phases

### Phase 1: Reliability Guardrails

**Goal:** User can trust that a successful run did not quietly rely on stale TECH cache data, hidden missing logs, or silently broken validation.  
**Depends on:** Nothing (first phase)  
**Plans:** 2 plans

Plans:
- [x] 01-01: Add cache metadata and invalidation rules for TECH and other fragile fetch artifacts.
- [x] 01-02: Add explicit missing-log and validation-health reporting to pipeline output and tests.

**Details:**
- User can rerun the pipeline and get refreshed TECH cache behavior when season inputs or weighting assumptions change.
- User can see which player-season logs are still missing after a run instead of inferring it from bad outputs.
- User can see when a validation file failed or matched too few players to be trustworthy.

### Phase 2: Identity And Benchmark Fidelity

**Goal:** User can compare the same player population across Basketball Reference, NBA API, and benchmark files without brittle manual cleanup.  
**Depends on:** Phase 1  
**Plans:** 2 plans

Plans:
- [x] 02-01: Strengthen player identity resolution and add deterministic fallbacks for known cross-source mismatches.
- [x] 02-02: Normalize benchmark target handling so exact-league and Yahoo comparison paths are explicit and consistent.

**Details:**
- User can run the pipeline without draft-relevant players dropping out because of avoidable naming mismatches.
- User can execute season-specific 14-cat and Yahoo-style validations in one pass with clearly labeled outputs.
- User can trust benchmark inputs to represent the same players the model ranked.

### Phase 3: Miss Diagnostics

**Goal:** User can see the benchmark impact and largest misses after every run so the next fix is chosen from evidence instead of guesswork.  
**Depends on:** Phase 2  
**Plans:** 2 plans

Plans:
- [x] 03-01: Add benchmark delta reporting that compares current metrics with the previous baseline.
- [x] 03-02: Add top-miss summaries per validation target with enough context to drive the next modeling fix.

**Details:**
- User can inspect the largest misses for each benchmark directly from the run artifacts.
- User can compare new metrics against a prior baseline after a model change.
- User can identify which player profiles still dominate the error distribution.

### Phase 4: Projection Signal Upgrades

**Goal:** User gets projections that respond to broader role change and aging decline instead of leaning too heavily on points carry-forward.  
**Depends on:** Phase 3  
**Plans:** 2 plans

Plans:
- [x] 04-01: Expand trend weighting to consider broader category and role movement.
- [x] 04-02: Add a lightweight age and decline adjustment with focused regression tests.

**Details:**
- User gets trend adjustments informed by more than raw scoring movement.
- User sees obvious over-carried veterans discounted when decline signals are present.
- User can rerun validations and see whether the upgraded projection signals improved the target benchmarks.

### Phase 5: Category Calibration

**Goal:** User gets final rankings whose DD and TD contribution is calibrated against historical results instead of overpowering the rest of the profile.  
**Depends on:** Phase 4  
**Plans:** 2 plans

Plans:
- [x] 05-01: Analyze DD and TD contribution against benchmark miss patterns.
- [x] 05-02: Adjust scoring/calibration and verify the effect with rerun metrics.

**Details:**
- User can see DD and TD contribution reviewed against historical benchmark misses.
- User gets recalibrated category influence when DD or TD is dominating rankings unfairly.
- User can rerun validations after calibration and judge whether the ranking spread improved.

## Milestone Summary

**Key accomplishments:**
- Added metadata-aware cache envelopes and degraded-run reporting so stale or incomplete runs cannot silently look healthy.
- Centralized deterministic player identity matching and trust-tiered benchmark handling across NBA API and validation sources.
- Added persistent benchmark history, delta reporting, top-miss artifacts, and heuristic miss buckets for evidence-driven iteration.
- Replaced points-only trend weighting with a multicategory composite trend path plus capped role boost and light decline logic.
- Added explicit DD/TD contribution diagnostics and separate bounded milestone-stat calibration inside the scoring path.

**Issues resolved:**
- Silent cache reuse and silent validation failure modes.
- Cross-source accent/name mismatches that were dropping players like Alperen Sengun/Şengün.
- Lack of persistent benchmark baselines and miss artifacts.
- Unmeasured DD/TD distortion in historical benchmark misses.

**Issues deferred / carried forward:**
- Direct Yahoo export ingestion for historical exact-league validation.
- Unresolved NBA API edge cases for Jimmy Butler, Bojan Bogdanovic, and Saddiq Bey.
- Remaining miss concentration in breakout/role-growth and availability-driven profiles.

**Technical debt recorded at ship:**
- Phase 01 validation artifact is still only partially Nyquist-compliant.
- Automated git commit steps remained blocked by the local `.git/index.lock` permission issue.
